# 代码修改与交付

## 代码简洁

- 代码应尽可能简洁明了：少用冗余变量和迂回实现，能直接写清楚的不要拆成多余步骤。
- 用最小改动解决问题，不写与任务无关的代码。

## 注释

- 好代码应能自解释；只在非显而易见的业务逻辑或技术细节处写注释。
- 不要删除注释，除非已确认完全不再需要。
- 注释与代码不一致时，修改注释，不要直接删除。
- 新增或修改的注释使用中文。

## 提交与推送

- 代码修改并验证通过后，必须只提交本次相关改动并推送到当前分支，不要把用户的无关改动加入提交。
- Git 提交信息必须使用简洁、明确的中文，说明本次修改目的；禁止使用无意义文本或英文提交信息。
- 提交前检查暂存区、敏感信息和生成物，提交后确认工作区状态；推送后确认本地提交已到达对应远端分支。
- 用户明确要求不提交或不推送、当前处于 plan 模式、仓库没有远端，或权限及外部服务阻塞时不得强行执行；应保留本地改动并明确报告阻塞原因。
- 涉及 GitHub PAT 的非交互式推送遵守 `maintain-github-pat` skill，不得把凭据写入 remote URL、提交或日志。
